# 이더넷 카드(NIC)와 라우팅 테이블

## 개요

네트워크 통신은 크게 다음 두 가지 요소로 구성된다.

* NIC(Network Interface Card): 실제 패킷을 송수신하는 물리적 또는 가상 인터페이스
* Routing Table: 목적지까지의 경로를 결정하는 정보

둘은 서로 다른 역할을 수행하지만 함께 동작해야 한다.

---

# NIC의 역할

NIC는 네트워크에 연결되는 인터페이스이다.

예시:

```text
eth0 : 10.10.20.2/24
eth1 : 10.10.30.2/24
```

NIC가 연결된 네트워크에 대해서는 직접 통신이 가능하다.

예:

```text
10.10.20.2
↓
10.10.20.10
```

동일한 서브넷에 존재하므로 ARP를 통해 직접 통신한다.

---

# Routing Table의 역할

라우팅 테이블은 목적지까지의 다음 홉(Next-Hop)을 결정한다.

예:

```bash
ip route add 10.10.30.0/24 via 10.10.20.1
```

의미:

```text
10.10.30.0/24 네트워크는
10.10.20.1 에게 전달
```

라우팅 테이블은 목적지까지 직접 연결해주는 것이 아니라 다음 장비에게 전달할 경로를 알려주는 역할을 수행한다.

---

# 흔한 오해

## 잘못된 이해

```text
라우팅 테이블만 있으면
어떤 네트워크든 접근 가능하다.
```

이는 정확하지 않다.

---

# 올바른 이해

라우팅 테이블은 다음 홉을 알려줄 뿐이다.

최종적으로는 목적지 네트워크에 연결된 NIC를 가진 장비가 반드시 존재해야 한다.

예:

```text
DMZ
 ↓
FW1
 ↓
FW2
 ↓
Backend
```

FW1:

```bash
10.10.30.0/24 via FW2
```

FW1은 10.10.30.0/24 인터페이스가 없어도 된다.

하지만 FW2는 반드시:

```text
eth1 = 10.10.30.1/24
```

처럼 Backend 네트워크에 연결된 NIC를 가지고 있어야 한다.

---

# ARP와 NIC

최종 목적지로 패킷을 전달할 때는 반드시 ARP가 수행된다.

예:

```text
10.10.30.2 의 MAC 주소는?
```

ARP는 동일한 L2 네트워크에서만 동작한다.

따라서 목적지 네트워크에는 반드시 해당 네트워크에 연결된 NIC를 가진 장비가 존재해야 한다.

---

# 현재 프로젝트 예시

구조:

```text
10.10.20.0/24 (DMZ)
       |
   IPFire
       |
10.10.30.0/24 (Backend)
```

DMZ 서버:

```bash
ip route add 10.10.30.0/24 via 10.10.20.1
```

설정 가능.

하지만 IPFire는 반드시:

```text
ORANGE : 10.10.20.1/24
GREEN  : 10.10.30.1/24
```

인터페이스를 모두 가지고 있어야 한다.

그렇지 않으면 10.10.30.0/24 네트워크로 패킷을 전달할 수 없다.

---

# 결론

라우팅 테이블은 다음 홉을 결정하는 역할을 수행한다.

하지만 최종 목적지까지 패킷이 전달되기 위해서는 반드시 목적지 네트워크에 연결된 NIC를 가진 장비가 존재해야 한다.

즉,

```text
라우팅은 "누구에게 넘길지"를 결정하고,
NIC는 "실제로 어디로 전달할지"를 가능하게 한다.
```

따라서 목적지 네트워크에는 반드시 해당 네트워크에 연결된 인터페이스가 존재해야 한다.
